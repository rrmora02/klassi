## Hallazgos y arreglos aplicados

1. **Login automatizado bloqueado por verificación de dispositivo (bug de la
   suite, arreglado).** La instancia de Clerk pide `email_code` como segundo
   factor en navegadores nuevos, así que el flujo por contraseña de
   `@clerk/testing` se quedaba en `needs_second_factor` y toda prueba
   autenticada fallaba. `e2e/helpers.ts` ahora inicia sesión con **sign-in
   tokens** del Backend API (estrategia `ticket`), que completan la sesión sin
   segundo factor. No hace falta desactivar nada en Clerk.
2. **Selectores ambiguos (bugs de specs, arreglados).**
   - `instructor.spec.ts`: el inicio del instructor tiene dos links
     "Asistencia" legítimos (menú + acceso directo); el selector ahora se
     limita al menú de navegación.
   - `staff.spec.ts`: los tabs de Pagos incluyen el contador en el nombre
     accesible ("Pendientes 1"), por lo que `exact: true` no coincidía; ahora
     se usa regex de prefijo.
3. **Configuración del entorno E2E:** `E2E_INSTRUCTOR_EMAIL` está configurado
   con el mismo correo que `E2E_STAFF_EMAIL` (`raul.remo02@gmail.com`). El
   instructor real es `rrmora02@gmail.com` (confirmado por Raúl); esta corrida
   se hizo con ese valor. Conviene actualizar la variable del entorno para
   futuras corridas.
4. **Sin bugs de la app detectados por la suite**: las 13 fallas iniciales
   fueron todas de infraestructura de pruebas (login/selectores), no del
   producto. Observación menor: la página `/sign-in` registra un 404 en
   consola al cargar un recurso (no afecta el flujo; pendiente de identificar).

## Cómo reproducir

```bash
# 1. Postgres local + esquema + seed
npx prisma db push
DATABASE_URL=... npx tsx e2e-seed.local.ts

# 2. Build real
npm run build && npm start

# 3. Suite completa
E2E_BASE_URL=http://localhost:3000 \
E2E_INSTRUCTOR_EMAIL=rrmora02@gmail.com \
npx playwright test
```

Lo que la suite no cubre (push real en teléfono, correos, escrituras,
multi-tenant con dos escuelas) sigue en el checklist manual:
`docs/plan-pruebas-qa.md`.
